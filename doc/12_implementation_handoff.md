## 未回答事項と実装可能な暫定案
以下はAIの提案で、利用者の承認済み決定ではない。READMEの暫定案利用方針に従って設定として実装できる。実験開始前に使用値を固定し、結果とともに報告する。

| 項目 | 暫定案 | 残る問い |
|---|---|---|
| 今回配置への評価 | current_editとして同一episode内だけ使用 | 後続場面へ一般化する条件 |
| 一般的好み | 同一セッション内で有効、同一特徴の新しい明示的訂正で置換 | 保持期間・忘却・条件付き好み |
| scope不明 | uncertainとしてepisode内に限定、曖昧さを保存 | 確認質問をする基準 |
| 好みと逆方向の差分 | direction_guard=trueで成分更新を見送り、矛盾を保存 | 元式そのままとの比較範囲 |
| 根拠の再利用 | 同一採用episodeにつき一度。一般的好みは別の関連episodeにも使用可能 | 一度だけ消費する方式との比較 |
| 関連性 | 有効根拠の特徴と、利用者が要求・評価した関係が対応する場合のみ | 自由な自然言語での対応精度 |

全特徴の差分が出たからといって、保存された全好みに関連すると扱わない。初週は明示的な対応表と人手ラベルで関連性判定を検証する。根拠を保持することと、選好重みが更新されたことを区別する。初週の候補選択は更新済みwを使い、未採用の根拠で重みを仮更新しない。

## 明示方式の初稿：explicit_retained_delta
旧explicit_masked_deltaは現在発話だけを使う再現用。今回方式は保持根拠を使うため、別ID・版で記録する。以下の具体式は実装用の暫定案であり、有効性は未検証。

1. 発話からfeature_id、polarity、source_span、scope、対象・関係を抽出。一般的好み、配置への明示的評価、局所指示、単なる受容・訂正を区別する。
2. 根拠を発話・episode・提案IDに紐づけて保存。好みだけなら記録完了を返し、scene_revisionとwは不変。LLMの想像した好みを根拠にしない。
3. 採用時、最後の確定配置X0から最終案X1へのΔfを計算。有効かつ関連する根拠のある特徴だけmask m_k=1、他は0。初週は根拠頻度による係数を加えず二値マスクとする（旧式のHとは別）。
4. direction_guardが有効なら、根拠極性e_kとΔf_kの積が負の成分を除外する。極性をΔfに再度掛けて負の好みを正に変える実装にしない。
5. w_new=Π_{||w||2≤1}(w+η(m⊙Δf))。初期w=0、η=0.3、norm_cap=1を暫定値として設定する。
6. 採用イベントと使用根拠を記録。却下・失敗・未採用では重みを更新しない。同じ採用イベントの再送は同じ結果を返す。

no_updateはwを更新しない。no_separationは全採用差分を用い、m=1、direction_guardを適用しない。両者は同じη・射影・入力記録を使う。方式固有設定をログに残す。射影は非対象成分も縮小し得るため、加算マスクと最終値の変化を別々に報告する。

### 最小の検証例
- 「木陰が好き」→根拠保存のみ。「このベンチを木へ近づけて」→プレビュー→採用時に木陰近接度の差分で更新。過去根拠を使ったことをログで確認。
- 好み根拠が一切ない「ベンチを右へ」→採用して配置は変わるが、明示方式の加算更新はない。
- 提案に「露店が多すぎる」→今回episodeの負方向根拠を保存。露店を減らす修正案を採用した時に更新。発言だけでは採用しない。
- 好み根拠に反する変化、却下、二重採用、無関係な操作、訂正の反復も確認する。

## 初週の報告用成果物と受入条件
- 起動可能なUnityクライアントとPythonサービス、依存・起動手順、設定例、正式schema、限定指示の対応表。
- Unityで「好み入力→関連編集→プレビュー→採用→重み更新→後続提案」の一連の流れ。採用前と却下時には配置・重みを確定しない。
- 反映デモは、明示的好みと指示が両立し、候補間に特徴差があるシーンを使用。同じ候補集合で、重み利用により選択が変わることをranker単体でも確認する。
- Bの初稿は05の既存方針（指示・幾何filter、効用−変更コスト）を用いる。「少し」等の量的範囲・達成条件・距離候補は実装前に暫定の対応表として文書化し、無制限に移動させない。
- 3方式で共通記録を再生できるランナーとログ。手動根拠ラベルによるAの切り分け評価と、LLM抽出結果による評価を区別する。
- 根拠単独、無関連操作、配置評価、付随変化、訂正、矛盾、却下・再送を含むケース。学習しにくい例も残す。
- 初週は定量比較の予備結果。既知w*の評価は採否規則と設定を明記し、任意に置いた真値へ必ず収束するとは仮定しない。人の満足や対話全体の有効性は別評価。
- 保存対象：発話、根拠と有効状態、episodeと訂正関係、前後配置・特徴、候補・順位、採否、更新前後のw、マスク、射影係数、時間・モデル・設定版。
