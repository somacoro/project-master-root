# 対話と画面

## 初期画面
3D広場、固定方位の俯瞰切替、テキスト入力、選択中物体の名称、処理状態、提案説明、採用・却下ボタン、修正欄を用意する。研究者用パネルは特徴・重み・制約違反・ログIDを表示できるが、被験者用画面では隠す。

## 状態遷移
idle → interpreting → planning → preview → accept→idle。
preview → revise→planning→preview、preview → reject→idle。
対象不明はclarificationへ、失敗は確定配置を保持してidleへ。processing中の重複送信は抑止。セッション終了時の未採用案は破棄し、その事実を記録する。

## 対象解決
「これ」: 選択中IDを優先、なければ直前の明確な参照、解決できなければ確認。
「入口近くのベンチ」: 種類と入口距離で照合。同距離などで対象が不明ならハイライトして確認。
「ベンチを増やして」: 種類に対する追加操作。「ベンチを右へ」: 一体か全体か不明なら会話・選択から解決、無理なら確認。
「全部のベンチ」: 一括操作。「赤いベンチ」: 色属性がある場合のみ解決。存在しない属性を視覚的に推測した扱いにしない。
対象の曖昧さと、好みに依存する編集方針の曖昧さを分離する。前者は確認、後者は推定重みを利用する。

## プレビューの契約
確定配置X0を保持したまま提案P1を表示する。P1への「もう少し近く」はP1基準で生成するが、必須条件は引き継ぐ。新しい指示が過去条件を明示的に撤回した場合は履歴付きで置換する。採用時はX0→最終Pの差分を使う。
全体を却下すればX0へ戻る。途中Pへ戻す履歴UIは後続機能。採用後の取り消しを追加する場合は配置だけでなく学習状態も対応するチェックポイントへ戻し、ログは消さない。

## フィードバック
ボタン採否は客観イベント。自然言語の修正は根拠を含むこともある。初期版で「いいですね」を自動採用せず、採用ボタンの確認へ誘導する。
提案説明例: 「入口のベンチを木に近づけました。ほかの物体はそのままです」。未知の好みを断定せず、曖昧指示では「今回は露店を減らす方向で解釈しました」と短く示す。

## 将来
複数案は同じ確定配置から生成し、比較中は同じ視点を使用する。直接操作もbefore/afterと操作対象をイベント化する。マウス編集がされたというだけで持続的選好と確定しない。

## 好みだけの入力
「木陰が好き」だけなら、配置を勝手に変更せず、好みを記録したことを表示する。配置・重みはその場では不変。後続の関連編集が採用された時に、保存根拠に紐づけて更新する。研究者パネルで有効根拠・学習前後の重み・更新理由を追えるようにする。
配置への明示的評価は根拠として保存するが、評価だけで自動採用しない。却下案・未採用案の差分では更新しない。今回評価の有効範囲・保持期間は未決設定として12を参照。
