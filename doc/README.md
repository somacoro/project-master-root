## 文書の扱い
- 「確定」は利用者が合意した要件。「暫定」は初稿の実装案であり、研究上の正解ではない。
- 暫定案は小さな実装・動作確認に用いてよい。変更時は理由と影響を決定記録に残す。研究目的や必須範囲を変更する場合は利用者と相談する。
- 初期仕様は単一案提示・6特徴固定。複数案、直接操作、動的特徴生成は後続拡張。
- 仕様の確定状況と、未実装／実装中／動作確認済み／実験検証済みは別に管理する。
- 本文の新しい明示的決定を、過去資料の計画より優先する。資料と異なる計算式・パラメータは変更として記録する。
- examplesのJSONは入力形式・テストデータの案。システム実装、JSON Schema、テストランナーそのものではない。
