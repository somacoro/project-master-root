# 幾何・特徴量・候補選択

以下の具体式は初期実装用の暫定案。資料の概念名は維持するが、実空間への接続を検証してから式とパラメータを実験用に凍結する。

## 幾何制約
全footprintが境界内、物体間footprintが重ならない、禁止領域と交差しないことを必須とする。境界接触を許すか、離隔epsilon、通路の必要幅は設定化し、テストと同じ値を使う。初期案は接触許容、数値許容1e-6m、追加離隔0m。実施設計の法規・安全性を保証するものではない。
対象外の物体は原則固定。衝突回避のために勝手に他の物体を移動させない。敷地を塞ぐ要求などは実行不能と説明する。出入口間の経路保持は設定で有効化でき、実験開始前に条件を固定する。

## 初期6特徴
全て[0,1]で値が大きいほど当該性質が強い。好むか嫌うかは符号付き重みで表す。

| ID | 名前 | 初期計算案 |
|---|---|---|
| shade_proximity | 木陰近接度 | 各ベンチから最近傍樹木中心までの距離dについてexp(-(d-2.5)^2/(2×1.0^2))を平均 |
| central_openness | 中央余白度 | 広場中央の評価領域に中心を持つ最大空虚円の半径rを5mで割りclip |
| path_efficiency | 動線効率 | 出入口ペアの直線距離／障害物を避けた経路長の平均 |
| view_openness | 視線開放度 | ベンチ前方60度内の複数rayの遮蔽物までの距離を8mで正規化して平均 |
| greenery | 緑化充足度 | min(樹木数／基準樹木数,1) |
| activity | 賑わい度 | min(露店数／基準露店数,1) |

暫定パラメータ: 中央評価領域はx=[5,15],z=[2.5,7.5]、円中心候補格子0.25m、経路格子0.25m、歩行半径0.3m、rayは視点高さ1.2m・角度-30,-20,-10,0,10,20,30度、基準樹木数5、基準露店数3。全て設定ファイルに置く。中央領域制限は「中央余白」という名前に合わせた初稿の追加仕様であり、過去資料の敷地全体の最大空虚円と同一ではない。比較時は定義版を区別する。
経路は歩行半径で障害物を膨張して探索し、斜め移動の角抜けを禁止。rayは自分のベンチを除外し、視点高さに達する障害物を対象とする。初期の賑わいは露店数の代理指標であり、人流や実際の賑わいを測ったと主張しない。木陰も実日射ではない。

## 空集合と異常値
- 木またはベンチが0: shade_proximity=0。ベンチ0: view_openness=0。診断に対象なしを残す。
- 物体0: 中央余白は境界だけで計算。他の数ベース特徴は0。
- 経路なし: path_efficiency=0。出入口定義欠落・重複は設定エラーとして実験開始を拒否。
- 数値異常や必要属性欠落: 0で握りつぶさずinvalid。特徴計算失敗の候補は採用しない。
- 対象なしからありへの変化は、母数変化としてログに残す。固定次元でも推定の安定性が自動的に保証されるわけではない。

## 効用と拡張
U_w(X)=Σ_{k∈S} w_k f_k(X)。初期Sは6種固定。FeatureRegistryを通じて計算し、配列の位置に意味を埋め込まない。
将来はLLMが特徴定義・式を提案し、検証済みcalculatorとして登録、セッション開始時にSを選ぶ。未検証コードを主プロセスで実行しない。式の検証には有限値・正規化・期待挙動・実行時間・入力依存を含める。途中変更には新しいfeature_set_version、履歴再計算、重み移行または再学習が必要。初期版は途中変更を禁止する。

## 曖昧指示から1案を選ぶ
1. LLMが要求を解釈し、定義済み操作・関係・編集方針へ変換する。好みの重みや最終座標は直接出力させない。
2. 具体指示は対象限定の候補を作る。曖昧指示は複数の解釈を残し、どの解釈を使ったかを記録する。
3. 操作テンプレート、格子サンプル、局所探索で有限候補を生成。初期案は候補上限64、探索上限2秒、seed付き。LLM時間は別に測る。
4. 幾何制約と必須指示を満たさない候補は除外する。指示を満たす候補がなければ失敗または確認。
5. 残った候補を、定性的指示の適合段階、U_w(X)-λ×変更コストの順で比較する。λは設定化（初期案0.1）。異なる尺度の混合は予備テストで確認する。
6. 最終検証を通した1案を表示。内部候補は複数でもよい。

変更コストは移動距離を敷地対角長で割った和、最小回転角/180の和、追加・削除数の和。具体指示に必要な変更を罰して何もしない案が勝たないよう、指示達成を先に判定する。
初期重み0では効用で順位がつかない。指示適合と変更量、安定したtie-breakで選ぶ。単なる「落ち着く」等は対応する意味ルールの仮説を候補に適用し、利用者に解釈を短く示す。重みだけで言葉の意味を決めない。

将来の比較案は、推定効用が高い案、別特徴を重視した多様な案、指示・幾何制約内の探索案とする。重みを変えて候補を生成しても、実利用者の保存重みを書き換えない。単純な順位2位ではなく特徴差で多様性を確認する。
