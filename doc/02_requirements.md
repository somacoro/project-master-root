# 要件

## 確定した環境と範囲
- macOS、Unity 6000.3.13f1。実験用PCが別の場合の仕様は未確認。
- Unity: 表示・操作・シーン取得。Python: LLM・特徴計算・探索・学習。
- 初期空間: 平坦な20m×10mの広場、樹木・ベンチ・露店。
- 操作: 移動・回転・追加・削除。サイズ変更・地形編集は初期対象外。
- 初期は単一案提示、6特徴固定。LLMのモデル・提供元は変更可能。
- クリック選択に加えて言語による種類・位置関係・複数対象指定を扱う。

## 初期必須要件
| ID | 要件 | 完了の根拠 |
|---|---|---|
| R01 | ID付きのシーンを取得・復元 | 保存と再読込で同一状態 |
| R02 | 明示的操作と対象解決 | テスト入力で指定物体のみ変更 |
| R03 | 曖昧指示への候補生成と1案選択 | 複数の重み設定で候補選択を検証 |
| R04 | プレビュー・採用・却下・修正 | 確定状態と未確定状態の分離 |
| R05 | 6特徴の算出と線形効用 | 手計算例、ゼロ個、増減時のテスト |
| R06 | 学習方式を切替可能 | 同じ記録を各方式で再生可能 |
| R07 | 幾何制約と失敗時の保持 | 不正候補を確定しない |
| R08 | 全処理の追跡ログ | 発話から配置・学習までIDで結合 |
| R09 | LLM交換・モック実行 | APIなしで基本テスト可能 |
| R10 | シナリオ・模擬利用者接続 | UI操作なしでも対話を実行可能 |

採用／却下ボタンと修正欄は暫定UI案。最終アンケートや実験条件は未確定。

## 後続拡張
複数の配置案の比較、直接ドラッグ編集、物体カテゴリ追加、PLATEAU接続、LLMによる特徴式生成、セッション開始時の特徴選択。これらの完成を初期版の条件にしない。

## オブジェクト登録
種類をコード各所の3分岐で固定しない。type_id、表示名、選択用属性、Prefab参照、標準寸法、footprint、移動・回転可否、特徴計算用の役割タグをカタログで管理する。新カテゴリはカタログと必要な計算処理を追加する。未対応の性質を既存特徴で評価できると仮定しない。

## 実行品質
処理中もUnityの操作画面を停止させない。キャンセル・タイムアウト・接続失敗を表示する。失敗を「採用された変更なし」と混同しない。APIキーをUnityアセット、Git、ログに保存しない。モデルの出力はデータとして検証し、初期版で任意コードとして実行しない。

## 2026-11-17の優先順位
