このリポジトリに、修士研究用のUnity都市広場編集システムを実装してください。まずdoc-edit/12_implementation_handoff.md、次にdoc-edit/README.mdから順に資料を読み、確定要件・暫定仕様・未決事項を区別してください。2026-11-17の利用者申告では全未実装です。既存資産の有無は現物を確認してください。2026-11-24目標でUnity上の自然言語編集・明示的選好学習・後続提案への反映を動かし、学習なし／分離なし／明示のみの初期比較を示したいです。Pythonだけの実験で完了にしないでください。計画やサンプルJSONを実装済みと判断しないでください。

開発環境はmacOS、Unity 6000.3.13f1です。Unityで表示・操作、PythonでLLM呼び出し・特徴計算・探索・選好学習を行います。最初は単一案提示・6特徴・樹木/ベンチ/露店・移動/回転/追加/削除です。

まず既存リポジトリと利用可能な実行環境を調べ、短い実装計画を作ってから実装を進めてください。既存プロジェクト設定・コード・文書を確認せず上書きしないでください。UnityのAPIや依存パッケージは対象バージョンの公式情報と実機で確認してください。環境がない場合は確認できた範囲を明示してください。

最初の到達点は、LLMモックで「シーン取得→構造化指示→候補生成→プレビュー→採用/却下→保存」を一巡させることです。その後、幾何、6特徴、対象解決、曖昧指示、LLM、選好学習、自動実験を順に接続してください。

特に守ること:
- 利用者が選んでいない案や未採用案で確定重みを更新しない。
- 対象不明を全体編集として補完しない。
- 好みのない局所指示は実行するが、有効な過去根拠もない場合は明示方式で加算学習しない。反復学習用の根拠は記録する。
- 同じ要求の失敗・訂正を独立した好みの反復として数えない。
- 特徴・物体種類・学習方式・モデルをコード全体に固定しない。
- 不正JSON、API失敗、幾何違反、古い提案、二重採用で状態を破壊しない。
- 数理利用者の真の重みとLLMペルソナの秘密情報を編集役へ渡さない。
- 初期版に複数案UI、直接ドラッグ、PLATEAU、LLM式生成を先行実装しない。
- 暫定値を有効性が実証された値と呼ばない。変更は決定記録へ残す。

examplesを参考に正式なschemaとテストランナーを実装し、09のテストを段階的に確認してください。各段階で、変更内容、実行したテスト、未確認事項、起動方法を報告し、進捗をdoc-editに更新してください。API課金を伴う大量実験や本実験を、動作確認の名目で無制限に開始しないでください。

## 今回の補足
明示方式はexplicit_retained_delta。一般的な好みと今回配置の明示的評価を保存し、好みだけでは重みを直接更新せず、後続の関連編集採用時に更新する。旧explicit_masked_deltaと混同しない。
12にある未回答事項は暫定設定として実装・記録し、確定仕様と呼ばない。反復は初週はログ保存まで。モデル・API予算が未設定でもモックによるUnity経路を完成させるが、実際の自然言語解釈は別途接続・検証し、固定シナリオ再生だけで達成と報告しない。
CLAUDE.mdはdoc/を参照しているため、今回明示されたdoc-edit/との差分を確認する。既存doc/と実装・Unity設定を無断で上書きしない。
